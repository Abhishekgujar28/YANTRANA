Technical Architecture

From railway data to an executable plan.

Data integration → canonical model → decision intelligence → optimisation → hard safety constraints → governance.

01Data & IntegrationTMS / SMMS / TDMS / BDMS equivalents, timetable, assets, resources and history.
02Canonical Data ModelMaintenanceTask · Asset · Corridor · TrainPath · BlockRequest · Resource · Approval · ExecutionLog.
03Decision IntelligencePriority, criticality, overdue assessment, duration risk and task compatibility.
04Constraint OptimisationCP-SAT / MILP / heuristic search for feasible corridor and block schedules.
05Hard Safety ConstraintsProtected movement, power isolation, S&T procedures, dependencies and resource conflicts.
06Governance & ExecutionRBAC, review, approval, locking, audit trail, execution and restoration status.
End-to-End Workflow

Demand → Intelligence → Approval → Execution.

YANTRANA recommends; authorized railway personnel review, approve and execute.

01 / INTAKE

Maintenance Demands

Engineering, TRD and S&T submit tasks, assets, duration and block requirements.

02 / INTELLIGENCE

Unify + Prioritise

Validate data, dependencies, criticality and cross-department compatibility.

03 / OPTIMISATION

Generate Plan

Solver creates candidates around timetable, resources and operational constraints.

04 / GOVERNANCE

Review + Approve

Authorized officers review, modify where required and approve the plan.

05 / FIELD

Execute + Learn

Actual execution returns to the platform for monitoring and replanning.

Disruption detected → affected corridor → re-optimise → review again
